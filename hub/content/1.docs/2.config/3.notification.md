## 邮件通知

通过 SMTP 发送，填好主机名与用户名后即启用。需先在邮箱服务商处开启 SMTP 服务并获取授权码。

**主机名**

邮箱的 SMTP 服务器地址，如 `smtp.163.com`、`smtp.qq.com`

**端口**

邮箱的 SMTP 端口，使用 `SSL/TLS` 时通常为 `465`

**安全性**

加密方式，可选 `SSL/TLS`、`STARTTLS`、无加密，默认为 `SSL/TLS`

**用户名**

发送通知的邮箱账号，即 SMTP 登录账号

**密码**

邮箱的 SMTP 授权码，不是邮箱登录密码

**发信人**

收件人看到的发件地址，为空则使用用户名

常见邮箱服务商的 SMTP 地址：

| 邮箱服务商 | SMTP 服务器 | 端口 |
| --- | --- | --- |
| 163 邮箱 | `smtp.163.com` | 465 |
| QQ 邮箱 | `smtp.qq.com` | 465 |
| Gmail | `smtp.gmail.com` | 587 |

> 不熟悉 SMTP 配置时，可参考 <https://blog.talen.top/posts/caffd8d6>

## 飞书通知

通过群自定义机器人推送给管理员，填好 Webhook 地址后即启用。

**Webhook 地址**

机器人地址，格式 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxx`，留空则不推送

**签名密钥**

机器人的签名密钥，仅当创建机器人时开启了签名校验才需要填写

## Telegram

通过 Bot 推送给管理员，Bot Token 与 Chat ID 都填写后即启用。需要先向 @BotFather 创建机器人，并把机器人拉进目标会话。

**Bot Token**

向 @BotFather 创建机器人后获得的凭证

**Chat ID**

目标会话 ID，频道也可以填写 `@channelname`

> **注意事项**
>
> `api.telegram.org` 在部分地区无法直连，投递失败会报 `context deadline exceeded`。此时会自动改走「基本配置」里的 Worker 代理地址。

## 关于通知

### 通知类型与接收方

不同事件投递到不同接收方：

| 通知类型 | 接收方 | 邮件 | 出站渠道 |
| --- | --- | --- | --- |
| 评论回复 | 被回复的用户 | ✅ | - |
| 新的评论 | 管理员 | ✅ | ✅ |
| 友链申请 | 管理员 | ✅ | ✅ |
| 反馈投诉 | 管理员 | ✅ | ✅ |
| RSS 订阅日报 | 管理员 | - | ✅ |

出站渠道只面向管理员，不发送评论回复；RSS 订阅日报只走出站渠道，不发送邮件。

异常友链提醒与系统通知（版本更新、官方公告）只在管理端站内提示，不经过上述渠道。

### 推送行为

评论、友链申请、反馈投诉在事件发生后的几秒内推送，RSS 订阅日报为每日定时推送。

同一事件会向每个已启用的渠道各推送一次，各渠道之间不做去重。
